      HTML Encoder & Decoder

      Encode text so it displays safely as plain text inside HTML, or decode HTML entities such as &lt;, &amp; and &#169; back into readable characters.

      Runs in your browser — your data is never uploaded or stored.

      About the HTML Encoder & Decoder

      Characters like < and & have special meaning in HTML. Encoding them is essential when showing code examples on a web page, and decoding is useful when text arrives full of entities from a CMS, feed or database.

      How to use the HTML Encoder & Decoder

      1. Paste your text, code or HTML into the input box.
      2. Click Encode to turn special characters into entities, or Decode to turn entities back into characters.
      3. For maximum compatibility with old systems, tick the option to encode non-ASCII characters as numeric entities.
      4. Copy the result into your page, template or database.

      Example use cases

      • Displaying HTML or code snippets as text in a blog post or documentation.
      • Cleaning up text exported from a CMS or RSS feed that is full of entities.
      • Escaping user-facing text before inserting it into an HTML template by hand.
      • Encoding special characters for systems that only accept ASCII.

      Characters that are encoded

      CharacterEntityWhy
      &&amp;Starts every entity
      <&lt;Starts an HTML tag
      >&gt;Ends an HTML tag
      "&quot;Ends an attribute value
      '&#39;Ends a single-quoted attribute

      Frequently asked questions

      Is HTML encoding enough to prevent XSS attacks?

      Encoding is an important part of preventing cross-site scripting when inserting text into HTML content, but it is not a complete solution. Text placed in JavaScript, URLs or CSS needs different escaping. In real applications, use your framework’s built-in escaping.

      Which named entities can be decoded?

      All standard HTML named entities (such as &nbsp;, &eacute; and &hearts;) plus decimal (&#169;) and hexadecimal (&#xA9;) numeric entities. Named entities must end with a semicolon.

      Is decoding safe if the input contains scripts?

      Yes. Decoding only converts entities to characters and shows them as plain text. Nothing in your input is executed.

      Is my text stored?

      No. Encoding and decoding happen locally in your browser.
