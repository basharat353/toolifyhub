      JSON Formatter & Validator

      Paste JSON to format it with clean indentation, compress it to a single line, or check it for errors. Invalid JSON is reported with the line and column of the problem and a pointer to the exact spot.

      Runs in your browser — your data is never uploaded or stored.

      About the JSON Formatter & Validator

      Unformatted JSON from APIs and log files is hard to read, and a single missing comma can break an application. Everything runs in your browser, so you can safely format API responses and configuration files that contain private data.

      How to use the JSON Formatter & Validator

      1. Paste your JSON into the input box, or click Load sample to try it out.
      2. Choose an indentation style and, if you like, tick “Sort keys alphabetically”.
      3. Click Format / Beautify for readable output, Minify for the smallest size, or Validate to check syntax only. Tip: press Ctrl + Enter to format.
      4. If there is an error, fix the line shown in the message and try again. Then copy or download the result.

      Example use cases

      • Reading and debugging API responses during development.
      • Finding the missing comma or bracket that breaks a configuration file.
      • Minifying JSON to reduce payload size before sending or storing it.
      • Sorting keys so two JSON files are easier to compare.
      • Checking webhook payloads and exported data before importing them.

      Common JSON errors

      • Trailing commas — {"a": 1,} is invalid; remove the last comma.
      • Single quotes — JSON requires double quotes: "name", not 'name'.
      • Unquoted keys — {name: "x"} is valid JavaScript, but not valid JSON.
      • Comments — standard JSON does not allow // or /* */ comments.
      • Special values — undefined, NaN and Infinity are not valid JSON values.

      Frequently asked questions

      Is my JSON sent to a server?

      No. Parsing and formatting use your browser’s built-in JSON engine, and nothing is uploaded or saved. This makes it safe for API keys, tokens and customer data — though it is always wise to avoid pasting secrets into any website you don’t trust.

      Why did a large number change after formatting?

      JavaScript stores numbers as 64-bit floating point, so integers larger than 9,007,199,254,740,991 (2^53 − 1) lose precision. Store such values (for example, IDs) as strings in your JSON.

      What happens to duplicate keys?

      JSON parsers keep only the last value for a duplicated key, so duplicates disappear after formatting. Validation does not flag them as errors because the JSON standard allows them, although it discourages them.

      Does it support JSON5 or comments?

      No. The tool follows the strict JSON standard (RFC 8259) used by APIs. Remove comments and trailing commas first.

      How large a file can I format?

      Several megabytes usually work fine. Very large files depend on your device’s memory and may make the page slow.
